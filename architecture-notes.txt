# Desk Health Dashboard — Architecture Notes
Last updated: 2026-10-22

## Architecture
- Monorepo: backend/ (Cloudflare Worker, TS), app/ (PWA source), firmware/ (ESP32-S3 + LVGL), tools/ (body map, snapshot renderer), mock/ (contract fixtures)
- Thin-client pattern — backend computes everything display-ready; device only fetches GET /api/dashboard and draws
- Single Worker as BFF for two clients: phone PWA (INGEST_TOKEN) and desk screen (DEVICE_TOKEN)
- Shared-UI pattern — firmware/ui/ is pure LVGL so the same code renders PNG snapshots on Linux and runs on the board
- Contract-first — mock/*.json fixtures + mock/validate.py define the /api/dashboard shape before any code exists

## Pipelines
- Health sync: iOS Shortcut -> POST /api/ingest (idempotent day overwrite) -> KV day:YYYY-MM-DD (planned)
- Manual logs: PWA -> POST /api/gym, /api/bp, PUT /api/config -> KV (planned)
- Display: ESP32 -> GET /api/dashboard every 10 min -> LVGL render (planned)
- Firmware build: push -> GitHub Actions (PlatformIO) -> merged .bin -> /flash page (ESP Web Tools, Web Serial) (planned)

## Security
- Auth: two bearer tokens — INGEST_TOKEN (writes + app reads), DEVICE_TOKEN (read-only /api/dashboard)
- Secrets handling: Cloudflare Worker secrets, GitHub Actions secrets, gitignored secrets.h / .dev.vars / .env*
- Known risks / open items: token stored in phone localStorage (single-user trade-off); no rate limiting yet
