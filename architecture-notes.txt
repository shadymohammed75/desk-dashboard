# Desk Health Dashboard — Architecture Notes
Last updated: 2026-10-22 (Phase 3)

## Architecture
- Monorepo: backend/ (Cloudflare Worker, TS), app/ (PWA source), firmware/ (ESP32-S3 + LVGL), tools/ (body map, snapshot renderer), mock/ (contract fixtures)
- Thin-client pattern — backend computes everything display-ready; device only fetches GET /api/dashboard and draws
- Single Worker as BFF for two clients: phone PWA (INGEST_TOKEN) and desk screen (DEVICE_TOKEN)
- Shared-UI pattern — firmware/ui/ is pure LVGL so the same code renders PNG snapshots on Linux and runs on the board
- Contract-first — mock/*.json fixtures + mock/validate.py define the /api/dashboard shape before any code exists
- Worker layout: index.ts (router + auth) -> validate.ts (input) -> store.ts (KV + write-side recompute) -> logic/*.ts (pure functions)
- Functional core / imperative shell — all rules (sleep, gym, score, XP, streak, coach, mascot) are pure and unit-tested; only store.ts touches KV
- Derived-state index — KV meta:days keeps one compact summary per day; streak, week strip, XP total and 7-day sleep avg read one key
- Recompute-not-increment — every write re-derives that day's summary, so re-ingesting can't double XP (idempotent by construction)
- XP total = sum of per-day points (no separate meta:xp counter); days older than 400 fold into archived_xp
- best_streak derived from history on read (meta:best_streak is only a floor), so rest-day growth counts without a write
- Celebrations generated on write by diffing before/after snapshots; ids are unique, active 30 min, priority level > streak > gym > goal
- Static Assets serve /app and /flash; Worker only runs for /api/* and the / -> /app/ redirect
- Phone app (backend/public/app): plain HTML/CSS/JS PWA, no build step, no framework; manifest + apple-touch-icon for Home Screen
- App state is one object S re-rendered wholesale (render()); form drafts (BP, plan) live in S so re-renders never wipe input
- Optimistic UI — apply locally, POST, replace with server's /api/today payload; on failure restore snapshot + toast
- Body map: tools/body_map/make_body.py generates body.svg (rounded, mirrored geometric shapes; one <path id> per muscle);
  writes the app's copy too; a vitest test asserts both copies are identical and every muscle id exists exactly once
- Asset pipeline (Python, run by hand, outputs committed): body.svg -> svg_to_lvgl.py -> A8 masks (firmware/ui/assets/body_assets.c)
  * one A8 alpha mask per muscle + silhouette fill/line per figure; tinted at runtime via image_recolor, so one mask serves all states
  * figure scaled to 0.64 (90×243 px) to fit the 480 px screen's right column (PLAN said ~140×380 — too tall); ~102 KiB pixels
- Mascot "Pip": original 32×32 pixel art drawn in code (tools/mascot/make_mascot.py), 5 moods -> PNGs for the app + ARGB8888 C
- tools/lvgl_c.py: shared emitter for lv_image_dsc_t (LVGL 9 header: magic/cf/flags/w/h/stride; ARGB8888 bytes are B,G,R,A)
- firmware/include/lv_conf.h: one LVGL config shared by firmware and the snapshot tool (RGB565, clib malloc)
- LVGL pinned to v9.3.0
- App icons generated from an SVG (score-ring motif + bolt) by tools/app_icons/make_icons.py

## Pipelines
- Health sync: iOS Shortcut -> POST /api/ingest (validated, day overwrite) -> KV day:DATE + meta:last_ingest -> recompute(DATE)
- Manual logs: PWA -> POST /api/gym (done/skip/undo, 7-day backfill) | /api/bp | PUT /api/config -> KV -> recompute(DATE)
- recompute(DATE): day record + config + bp -> summarizeDay -> meta:days, meta:best_streak, meta:celebrate (today only)
- Display: ESP32 -> GET /api/dashboard -> buildDashboard(state, now) computed live (mode, staleness, coach depend on the clock)
- Deploy: push to main -> Cloudflare Workers Builds (root backend/) -> wrangler deploy; KV namespace auto-provisioned on first deploy
- CI: .github/workflows/backend.yml -> typecheck, vitest, mock contract check, wrangler dry-run
- App E2E: backend/e2e/app.e2e.mjs (Playwright, iPhone 390×844) against wrangler dev — login, I trained, BP, plan, rollback, CSP
- Firmware build: push -> GitHub Actions (PlatformIO) -> merged .bin -> /flash page (ESP Web Tools, Web Serial) (planned)

## Security
- Auth: two bearer tokens — INGEST_TOKEN (writes + app reads), DEVICE_TOKEN (read-only /api/dashboard); constant-time compare
- Tokens < 24 chars refused (503); failed auth throttled by Workers Rate Limiting binding AUTH_LIMITER (20/min/IP -> 429)
- Input validation: hand-rolled validators (validate.ts), allowlisted fields + muscle ids, 1 MB body cap, 400 with clear message
- Headers: HSTS, CSP default-src 'none', X-Frame-Options DENY, nosniff, no-referrer, no-store on API; _headers for static
- App CSP (_headers /app/*): self-only scripts/styles/connect, no inline; DOM built with createElement/textContent (no innerHTML for data)
- App token: entered once, kept in localStorage (try/catch for Safari private mode); any 401 logs out; Log out button on Plan tab
- No CORS headers on purpose — app is same-origin, Shortcut/device don't need CORS
- Secrets handling: Cloudflare Worker secrets, GitHub Actions secrets, gitignored secrets.h / .dev.vars / .env* / *.pem
- Known risks / open items: token in phone localStorage (single-user trade-off); no KV backups yet (export endpoint later);
  concurrent writes can race on meta:days (self-heals on next write); past days judged with the current schedule
